# 会话清理

真正删除 DSH 会话。DSH 本身只有归档：归档只往一个 id 数组里加一项，日志一个字节都不动。这个插件补上磁盘层，并且**不需要退出应用**。

## 为什么不用手改 `workspace.json`

手工流程要求 `Cmd+Q` 退出、改 `~/.dsh/storages/workspace.json`、再重启，因为 Host 内存里持有注册表状态，任何侧栏操作都会把磁盘修改覆盖回去。

这个插件走的是官方 API：`ctx.workspaceRegistry` 的 `unarchiveSession()` 和 `detachSession()` 都是 durable 写入，写完会发 `domain/changed`，侧栏 feed 实时刷新。所以注册表可以热改，不存在被覆盖的问题。

## 一次删除做了什么

1. **预检** — 拒绝还有运行中轮次、子代理、后台任务或定时任务的会话（判据见下一节）。
2. **记账** — 在回收站目录写 `manifest.json`，记下 id、原路径、工作区、大小、标题。
3. **解绑** — 取消归档，再从所属工作区 `detachSession`。走 API，实时广播。
4. **搬走** — 同卷 `rename` 到 `<DSH_HOME>/trash/dsh-session-cleanup/<时间戳>/<会话 id>/`。原子、瞬时、不拷贝。
5. **清缓存** — 删掉这个会话的投影缓存文档。它是派生数据，删失败只记警告。
6. **广播** — `api-session/removed`，客户端立刻丢行。
7. **报告** — 逐条结果与释放字节数。

删除必须同时动注册表和文件：侧栏的行来自「live 会话 ∪ 持久化 listing」，`workspace.json` 的 `sessionIds` 只决定归到哪个工作区。只解绑不删文件，行会掉进「未分组」还在侧栏；只删文件不解绑，留下点开报 `session/not-found` 的空行。

## 「能不能删」的判据

**不看 `live`，只看有没有真的在跑。**

这是实测后改的结论。DSH 从不驱逐打开过的会话——归档也不驱逐——所以 `ctx.sessions.list()` 里长期躺着所有你打开过的会话。在一台有 4 个历史会话的机器上，4 个全部 `live: true`。如果按「live 即拒绝」处理，这个插件几乎删不掉任何东西。

真正的判据是 `ctx.waterfall('workspace/session-activity')`：组合里的提供者会报告这个会话上还有没有运行中的轮次（`turn`）、子代理（`subagent`）、后台任务（`job`）或定时任务（`schedule`）。有就拒绝，没有就允许。

页面上的状态标签对应关系：

| 标签 | 含义 | 可删 |
|---|---|---|
| 有任务 | 有运行中的轮次 / 子代理 / 后台任务 / 定时任务 | 否 |
| 已归档 | 在归档集合里 | 是 |
| 空闲驻留 | 还在内存里，但没在工作 | 是 |
| 可删除 | 不在内存里 | 是 |

## 两个容易踩的坑

### `api-session/removed` 不等于「日志删掉了」

它的语义是「Agent 被释放」，只清 Client 侧的缓存，**不驱逐 Host 的会话对象**。所以删完之后，`ctx.sessions.list()` 仍然会返回那个会话，`sessionPersistence.stat()` 却已经没有它了。

如果盘点时把这种残留当作普通会话列出来，页面上就会出现一行「删掉了但还在」的记录，看起来像删除失败。

插件用日志目录是否存在来区分：

- 持久化里没有、但日志目录还在 → 新建后尚未落盘，正常列出，不可删；
- 持久化里没有、日志目录也不在 → 已删除的内存残留，从列表排除。

代价是：删掉一个驻留但空闲的会话后，Host 内存里的对象要等到进程重启才消失。这期间它不会出现在侧栏（日志已不在），也不会在插件列表里（已排除），属于无害残留。

### locale 服务晚于插件就绪

Client 侧在 `apply()` 里直接 `ctx.get('locale')` 拿到的是 `undefined`，因为 locale 服务还没起来。表现是界面文案全部回落成英文，而且不会报错——只会安静地显示 `Session cleanup` 而不是「会话清理」。

正确做法是先试一次，拿不到就 `ctx.inject(['locale'], ...)` 等它，就绪后再绑定字典并通知订阅者刷新。宿主的 `dsh-profile-stats` 也是这么处理的。

## 回收站与还原

删掉的日志不会立刻消失，而是停在回收站里，默认保留 7 天（`retentionDays`，可在 `cordis.patch.yml` 里改）。

- **还原** — 把日志 `rename` 回原位，再 `attachSession` 挂回工作区。工作区目录已经不存在时，会话会落到「未分组」，不算失败。
- **永久删除** — 只在保留期过后可用，必须显式点名那一个批次。

回收站目录名是 `YYYYMMDD-HHmmss`，同一秒内发生多次操作时追加 `-1`、`-2` 后缀。用非递归 `mkdir` 分配，已存在就换下一个后缀重试——否则同一秒的两次操作会撞名，后一次把前一次的 `manifest.json` 覆盖掉，前一批就永久失去还原能力。

## 孤儿清理

- **孤儿日志目录** — 磁盘上有、注册表里没有。它们本来就不出现在侧栏，删掉不会留下报错的行。同样先进回收站。
- **孤儿投影缓存** — 没有对应日志的派生数据。缓存过期只会让回放慢一点，不会算错，所以直接删，不备份。

## 限制

- 运行中的会话不能删。插件不做「自动停掉再删」：删除是不可逆的权威操作，需要人确认，而且你正在看的那个会话天然属于这一类。
- 附件库 `~/.dsh/attachments` 是内容寻址、没有引用计数的，删会话不会回收它。这部分留待后续版本。
- 插件不注册 agent 工具、不写系统提示词，对模型完全不可见，运行期不消耗 token。

## 数据位置

| 内容 | 路径 |
|---|---|
| 会话日志 | `<DSH_HOME>/sessions/<工作区编码>/<会话 id>/` |
| 投影缓存 | `<DSH_HOME>/storages/session_projcache/sessions/<会话 id>.json` |
| 回收站 | `<DSH_HOME>/trash/dsh-session-cleanup/<时间戳>/` |

`<DSH_HOME>` 默认是 `~/.dsh`，可用 `DSH_HOME` 覆盖。

## 实测记录

以下都在 DSH `0.2.2-rc.5` / macOS 上跑过真实数据，不是推演。

| 验证项 | 结果 |
|---|---|
| 孤儿缓存清理 | 8 个 → 0，投影缓存目录 768 KB → 500 KB |
| 真实删除一个会话 | 日志进回收站，`workspace.json` 里彻底消失（不在任何工作区，也不在归档集合） |
| 还原 | 日志归位、工作区挂回、回收站自动清空 |
| 数据完整性 | 还原前后均为 30,694 字节，完全一致 |
| 保留期保护 | 7 天内 `empty-trash` 返回 `too-young`，拒绝永久删除 |
| 界面闭环 | 勾选 → 确认框 → 删除 → 提示条 → 回收站 → 点还原 → 侧栏恢复 |
| 状态判定 | 5 个空闲会话显示「空闲驻留」可删，1 个有 `turn`+`job` 的显示「有任务」且勾选框禁用 |

顺带确认了一个安全前提：JSONL 后端的 append 走 `open(path, 'a')` 而不是长期持有 fd，所以日志目录被移走后，目录不存在会报 ENOENT，不会静默重建文件。
